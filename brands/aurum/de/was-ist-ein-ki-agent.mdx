## Was ist ein KI-Agent?

Ein KI-Agent ist, einfach erklärt, ein Sprachmodell, das Werkzeuge und ein Ziel bekommen hat und in mehreren Schritten darauf hinarbeitet. Er entscheidet, was er als Nächstes nachschaut oder erledigt, benutzt dafür ein Werkzeug, liest das Ergebnis und macht weiter, bis das Ziel erreicht ist oder er nicht mehr weiterkommt. Ein Chatbot in einem Browserfenster beantwortet eine Frage. Ein Agent handelt in den Systemen, auf die er Zugriff hat. Im KMU-Büro heisst das zum Beispiel: ein Postfach sortieren, eine Antwort vorbereiten oder eine Auskunft zusammensuchen, die in drei Systemen verteilt ist.

[Anthropic](https://www.anthropic.com/engineering/building-effective-agents), ein Hersteller solcher Modelle, zieht die Grenze so: Bei einem festen Ablauf laufen Modell und Werkzeuge über vorher festgelegte Pfade. Bei einem Agenten steuert das Modell selbst, welche Schritte und Werkzeuge es nutzt. Kurz gesagt: Beim festen Ablauf legen Sie den Weg vorher fest. Beim Agenten wählt ihn das Modell.

## Wie sich ein Agent von Chat und Workflow unterscheidet

Im Alltag werden drei Dinge vermischt. **Chat** heisst: Sie stellen eine Frage, das Modell antwortet, der Vorgang endet. **Workflow** heisst: dieselbe Kette von Schritten bei jedem Durchlauf, oft ohne dass das Modell den Weg wählt. **Agent** heisst: das Ziel ist fix, der Weg kann von Fall zu Fall wechseln, weil das Modell entscheidet, welches Werkzeug als Nächstes passt.

Der Unterschied zwischen Regel, Workflow und Modell zeigt der Text zu [Digitalisierung, Automatisierung und KI](/de/prozess-check/blog/unterschied-digitalisierung-automatisierung-ki) an einer Lieferantenrechnung. Welcher Ablauf in Ihrem Betrieb zuerst drankommt, mit oder ohne Agent, steht in [welchen Ablauf zuerst automatisieren](/de/prozess-check/blog/welchen-ablauf-zuerst-automatisieren).

## Was ein KI-Agent im KMU-Büro kann

Ein Agent lohnt sich dort, wo der nächste Schritt davon abhängt, was der vorherige ergeben hat. In vielen Büros passen drei Arbeiten zu dieser Beschreibung.

**Zuordnen:** Der Agent liest neue Mails im Sammelpostfach, erkennt, ob es eine Bestellung, eine Reklamation oder eine Frage ist, und weist sie mit einer Zeile Zusammenfassung der richtigen Person zu. **Entwerfen:** Zu einer Kundenfrage sucht er die letzte Bestellung und die Preisliste heraus und bereitet eine Antwort vor, die jemand liest, bevor sie rausgeht. **Nachschlagen über mehrere Systeme:** «Wo ist die Lieferung für diesen Kunden?» heisst, die Auftragsliste, die Versandbestätigung im Postfach und eine Notiz im CRM anzuschauen. Der Agent sammelt die drei Antworten und schreibt eine.

In allen drei Fällen ändert sich der Weg von Fall zu Fall. Genau dort ist ein Modell, das seine Schritte selbst wählt, seinen Preis wert. Copilot in Microsoft 365 oder vergleichbare Assistenten in Ihrer Suite können einzelne Schritte unterstützen; ein «Agent» im engeren Sinn verbindet mehrere Werkzeuge mit einem klaren Ziel und läuft ohne dass jede Zwischenentscheidung vorgegeben ist.

## Was ein KI-Agent nicht unbeaufsichtigt tun sollte

Ein Agent sollte keine Zahlungen auslösen, keine verbindlichen Antworten verschicken, keine Daten löschen und nichts tun, was keine Person prüft. Verbindlich ist alles, worauf sich eine Kundin berufen kann: ein Preis, ein Liefertermin, eine Zusage zu Bedingungen.

Die [OWASP-Liste der Risiken für Anwendungen mit Sprachmodellen](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/) nennt das «Excessive Agency»: schädliche Aktionen, die aus unerwarteten, mehrdeutigen oder manipulierten Antworten des Modells folgen. Als Ursachen nennt sie zu viele Funktionen, zu viele Berechtigungen und zu viel Eigenständigkeit. Die Empfehlung: Folgenreiche Aktionen gibt ein Mensch frei. Für Agenten, die Mails lesen, kommt ein besonderes Risiko dazu. Text in einer Mail oder einer Datei kann Anweisungen enthalten, die das Modell dann befolgt. OWASP führt das als [indirekte Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/).

## Daten und Schatten-KI im Schweizer Büro

Agenten brauchen Zugriff auf echte Daten: Mails, Kundenlisten, Verträge. Kundendaten und interne Zahlen gehören nicht in kostenlose Chat-Konten ohne Vertrag und ohne klare Speicherregeln. Das revidierte DSG verlangt angemessene technische und organisatorische Massnahmen; welche Tools Ihr Betrieb erlaubt, ist eine Geschäftsentscheidung, keine Modellfrage.

Wenn Mitarbeitende bereits privat ChatGPT für Büroarbeit nutzen, haben Sie keinen Agenten, sondern Schatten-KI ohne Protokoll. Ein Agent im Betrieb braucht deshalb klare Grenzen: welche Systeme, welche Konten, wer freigibt, was geloggt wird.

## Wer mit Agenten lieber wartet

Nicht jedes KMU braucht einen Agenten, um KI nutzbar zu machen. Wenn Ihr Problem ein fester Ablauf mit wenigen Ausnahmen ist, reicht oft eine Regel oder ein einfacher Workflow. Wenn nur eine Person im Betrieb überhaupt IT-Zugänge hat, fehlt zuerst die Basis, nicht das Modell. Wenn die Arbeit selten vorkommt, übersteigen Einrichtung und Prüfung den Nutzen.

## Der Fehler: ein Agent für eine Arbeit, die eine feste Regel zuverlässig erledigt

Der häufigste Fehler ist, einen Agenten dort einzusetzen, wo eine feste Regel die Arbeit schon jedes Mal richtig macht. «Jedes PDF von diesem Lieferanten kommt in diesen Ordner und geht an diese Person zum Visum» hat genau einen richtigen Weg. Eine Regel geht ihn fast ohne Kosten pro Durchlauf, und Sie sehen im Nachhinein, warum sie was getan hat. Ein Agent bringt Schwankung genau dort hinein, wo Sie keine wollen, und jeder Durchlauf kostet mehr.
