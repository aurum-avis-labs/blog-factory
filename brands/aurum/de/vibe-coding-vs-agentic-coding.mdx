**Vibe Coding:** Prompt rein, App raus, schnell und visuell überzeugend. **Agentic Coding:** die KI arbeitet im eigenen Repo, mit Tests und Pipeline. Der erste Modus reicht für Demos. Sobald du verkaufen willst, brauchst du den zweiten. Der häufigste Bruch: Teams bleiben zu lange im ersten Modus. Grenzen und Checkliste: [Produktionsreife von Vibe-Coded Apps](/de/blog/ist-deine-vibe-coded-app-produktionsreif).

## Was Vibe Coding ist

Vibe Coding ist KI zuerst, Ingenieur optional. Replit, Lovable, Bolt.new und v0 sind darauf ausgelegt, aus einem Prompt in normaler Sprache eine ganze Anwendung zu erzeugen. Den Code musst du nicht verstehen. Du beschreibst, was du willst, die KI baut, du reagierst, du iterierst.

Der Geschwindigkeitsvorteil ist real. Was ein kleines Team früher in zwei Wochen gebaut hat, schafft ein Gründer heute an zwei Tagen. Auch der Zugang hat sich geändert. Gründer mit tiefem Fachwissen und ohne Engineering-Hintergrund bauen funktionsfähige Prototypen, ohne einen technischen Co-Founder zu brauchen.

Für die passenden Fälle ist Vibe Coding das richtige Werkzeug: Investorendemos, Hypothesentests, Concierge-MVPs, Landingpage-Experimente. Überall, wo du lernen willst und Zuverlässigkeit noch keine Rolle spielt.

Schwierig wird es, wenn Gründer das Werkzeug weiterverwenden, nachdem es für die Aufgabe nicht mehr passt.

## Was Agentic Coding ist

Agentic Coding läuft anders. Cursor, Claude Code und GitHub Copilot Workspace arbeiten mit Entwicklern zusammen. Ein KI-Agent schreibt Code, führt Tests aus, liest Fehlermeldungen, durchsucht die Codebasis und iteriert über mehrere Dateien. Das passiert in einer echten Engineering-Umgebung: Versionskontrolle, CI/CD, Code Review, ein echtes Datenbankschema, ein Deployment, das in Produktion gehört.

Architektur entscheidet weiter ein Mensch. Die KI übernimmt einen grossen Teil der mechanischen Arbeit. Ein kleines, erfahrenes Team schafft damit, wofür früher ein viel grösseres Team nötig war. Der Output ist von Anfang an produktionsreif, weil die Entscheidungen von Menschen kommen und nicht aus einem Prompt.

In diesem Modus arbeiten wir: Agentic Coding auf einem produktionsreifen Stack.

## Drei Modi, KI im Bau

Die drei Modi liegen auf einer Linie: vom schnellen Ausprobieren bis zum Repo mit Tests und Pipeline.

**Modus 1, Vibe Coding.** Die KI erzeugt, der Mensch reagiert. Tools: Replit, Lovable, Bolt.new. Schnell, zugänglich, gut fürs Ausprobieren und für die Validierung. Der Output ist meist nicht produktionsreif. Engineering-Wissen brauchst du keins. Damit kommst du schnell zu einem Prototyp. Dieselbe Lücke zeigt sich, sobald der Code in Produktion soll.

**Modus 2, Agentic Coding.** Die KI führt aus, eine Entwicklerin oder ein Entwickler gibt die Richtung. Tools: Cursor, Claude Code. Eine erfahrene Person setzt die Architektur, schreibt die kritische Logik und prüft den Output. Der Agent übernimmt Umsetzung, Refactoring, Tests und Iteration. Produktionsreif ist das, weil der Mensch die Entscheidungen verantwortet, an denen Qualität hängt.

**Modus 3, klassisches Engineering.** Der Mensch schreibt, die KI hilft. GitHub Copilot als Autocomplete, ChatGPT als Nachschlagewerk. Die KI ist ein Produktivitätswerkzeug, kein Agent. Weiter nützlich, und der langsamste der drei Modi.

In den meisten Diskussionen stehen Modus 1 und Modus 3 gegeneinander: Vibe Coding gegen «echte» Entwicklung. Modus 2 fehlt in der Rahmung. Dort passiert im Alltag am meisten.

## Wo Vibe-Coding an die Decke kommt

Vibe-gebaute Anwendungen teilen ein Muster: die KI optimiert auf «läuft in der Demo», nicht auf «läuft im Betrieb». Für den Fall, für den die Tools gebaut sind, ist das passend. Beim Skalieren kommen dieselben Fehler immer wieder.

Die Anmeldung sieht richtig aus, die Berechtigungen sind flach. Das Datenbankschema trägt den Normalfall und bricht unter gleichzeitiger Last oder an den Rändern. Fehlerbehandlung fehlt oder bleibt an der Oberfläche. Die Infrastruktur ist das, was die Plattform mitliefert, und du siehst nicht, was passiert, wenn sie ausfällt.

Wir sehen das immer wieder. Ein Gründer baut mit Replit oder Lovable etwas, das beeindruckt. Die ersten Nutzer sind begeistert, zahlende Kunden kommen dazu, und dann tut die App Dinge, die sie nicht tun sollte. Daten verschwinden. Funktionen brechen für einzelne Nutzer. Die Leistung bricht ein. Der Gründer geht zurück zum KI-Tool, die KI erzeugt Korrekturen, die neue Probleme einführen. Irgendwann schaut eine Entwicklerin auf den Code und sagt: neu bauen ist schneller als flicken.

Das Tool hat getan, wofür es gebaut ist. Der Gründer hat den Punkt verpasst, an dem er darüber hinaus war.

## Warum der Produktions-Stack die KI einengt

Die Qualität von KI-Code hängt stark an den Rahmenbedingungen, in denen die KI arbeitet.

Ein Vibe-Tool erzeugt Code ohne bestehende Codebasis, ohne Tests, die bestehen müssen, ohne Architektur, an die er sich halten muss, und ohne Deployment-Pipeline. Es erzeugt, was zum Prompt passt.

In einem Agentic-Setup arbeitet Cursor oder Claude Code in einer echten Codebasis: definierte Architektur, bestehende Tests, eine CI/CD-Pipeline, die grün sein muss, ein Datenbankschema, das gilt. Der Output muss in die Produktionsumgebung passen. Deshalb ist er produktionsreif.

Die Arbeit der Entwicklerin verschiebt sich. Weniger Boilerplate, mehr Architektur, Review und die Urteile, die eine KI unzuverlässig trifft. Ein kleines Team mit Agentic-Tools liefert deutlich mehr als ohne. Ein festes Verhältnis gibt es nicht. Domäne, Codebasis und Review-Kultur entscheiden.

## Welches Werkzeug zu welcher Phase

Du passt den Modus an die Phase.

**Validierung.** Du prüfst, ob die Idee trägt. Vibe Coding ist oft richtig. Tempo wiegt mehr als Zuverlässigkeit. Ein Ausfall kostet wenig. Replit, Lovable oder Bolt.new, schnell raus, lernen. Infrastruktur baust du nicht aus, bevor ein Signal da ist.

**Bau.** Du baust, was du verkaufst. Agentic Coding auf einem Produktions-Stack. Nachfragebelege sind da. Jetzt brauchst du etwas, das stabil genug ist für Verhaltensdaten, für zahlende Kunden und für die nächste Runde aus dem, was du gelernt hast. Hier verdient Modus 2 seinen Preis.

**Wachstum.** Agentic Coding mit mehr Engineering-Strenge. Architekturentscheidungen verstärken sich. Was du in der Bauphase festgelegt hast, bestimmt, was im Wachstum noch geht.

Die meisten Gründer bleiben in Modus 1, obwohl die Validierung vorbei ist. Er hat am Anfang so gut funktioniert, dass der Wechsel sich unnatürlich anfühlt.

## Wie wir bauen

Wir setzen keine Vibe-Coding-Tools ein (Lovable, Replit, Bolt.new und ähnliche Prompt-zu-App-Umgebungen), um die Produkte zu bauen, die wir für Gründer validieren. Wir arbeiten mit **Cursor** und **Claude Code** auf einem etablierten Framework und einem Template-Repository: klare Architekturmuster, wiederverwendbare Bausteine, von Anfang an Tests und Deploy-Pipelines. Kein isoliert erzeugter Code ohne tragende Codebasis.

Wir kombinieren stark strukturierten Code (Konventionen, Boilerplate, wiederkehrende Strukturen) mit agentischer Feature-Entwicklung im echten Repo. Agenten iterieren über Dateien, Tests und Fehlerbilder. Engineers halten Architektur, Security, Datenmodell und Deployment fest.

Für das Product Validation Package über 12 Wochen bauen wir ab Tag eins in diesem Setup: Azure, CI/CD, echte Authentifizierung, ein sauber entworfenes Datenbankschema, Error Monitoring und Alerting. Die KI übernimmt einen grossen Teil der Umsetzung in diesem Gerüst. Das Engineering-Urteil bleibt bei Menschen.

Ist das Produkt unzuverlässig, vermischen sich Nutzung und Qualitätsprobleme. Nutzer brechen nach zwei Sessions ab, und du weisst oft nicht, ob der Nutzen gefehlt hat oder ein Bug. Produktionsqualität ab Tag eins macht diese Vermischung kleiner. Andere Validierungsmethoden ersetzt sie nicht.
