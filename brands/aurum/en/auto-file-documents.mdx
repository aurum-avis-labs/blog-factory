## Name and file documents automatically

<p class="blog-lede">To name and file documents automatically, you fix one naming pattern and one folder rule, and you move a file only when both match. Anything unclear waits for a person.</p>

The tidy folder is not the ten-year archive. People find a file because the name is stable, not because someone remembers which desktop it was on.

This is for offices that already have the PDFs, from email or from a scan, and then lose them in "final", "final 2" and a personal drive. Turning paper into a PDF is the previous step, in [digitise incoming paper mail](/prozess-check/blog/digitise-paper-mail). A contract's notice date, once the file has a home, belongs in [track contract notice periods and renewals](/prozess-check/blog/contract-deadlines). If the files live in Microsoft 365, the wider map is [automate Microsoft 365](/prozess-check/blog/automate-microsoft-365). This page is only the name and the place.

## The name people can search for

Use a short pattern the whole office can say aloud. Date, then the other party's name as you already spell it in accounting, then the type: invoice, contract, letter, policy. A version number only when two files would otherwise collide. The date is the document date, not the day someone scanned it, unless the document has no date of its own.

"Final", "new" and the initials of whoever last touched the file are how search dies. Google's own help for shared drives asks an organisation to agree naming conventions so people find the drives and avoid clashes. Google's examples are prefixes for region, for status, and for whether a drive is external or internal ([Google Workspace Learning Center](https://support.google.com/a/users/answer/13015138)). Those examples are Google's, not a Swiss standard. They show the point: the pattern is decided once, in advance.

If you work in SharePoint, a column can carry the type and the party beside the file name. Microsoft documents a managed metadata column that you can set as required, so a value has to be entered ([Microsoft Support](https://support.microsoft.com/en-us/sharepoint/data-and-lists/create-a-managed-metadata-column)). A required field stops an empty save. It does not choose the right value. Someone still checks the first weeks until the pattern is dull.

## Folder rule, and the unclear pile

One rule. Either each client has a folder and the types sit inside it, or each type has a folder and the year sits inside it. Both rules work. Both rules at once, depending on who is in that day, do not. Write the rule in one sentence at the top of the library.

What already matches the pattern can move without a conversation: an invoice PDF whose name follows the pattern goes to the invoice place for that client. What does not match waits in an inbox folder for the day. A model may propose party and type by reading the first page. The same failures as with paper mail apply: the wrong date, a quote instead of a signed file, two documents in one PDF. Those stay in the inbox until a person names them. Do not let a nightly job file them "somewhere sensible".

<ul class="blog-checklist">
  <li>Write the name pattern and the folder rule on one page</li>
  <li>Point the scanner and the inbox at the waiting folder, not at the archive</li>
  <li>Let confident, patterned files move</li>
  <li>Leave uncertain files for a named person that day</li>
  <li>Stop using personal drives for the same documents</li>
</ul>

## Who may open the folder

A shared drive that everyone can open is the wrong place for wages and for medical notes. Google documents limited-access folders in shared drives: managers of the drive and people you add to the folder can open it. Other members see the name and cannot open the content ([Google Workspace Learning Center](https://support.google.com/a/users/answer/13015138)). Use that, or the equivalent permission in SharePoint, for personnel files. Client invoices can be wider, but not wider than the people who handle that client.

Do not fix permissions by making a private copy. A private copy is how two versions of the contract appear. One file, with the right people on it.

## Retention is not the same as a tidy name

Business books and accounting vouchers are kept for ten years, and an electronic copy is allowed only when it stays faithful and readable ([Art. 958f OR](https://www.fedlex.admin.ch/eli/cc/27/317_321_377/de)). A well-named PDF in a shared drive is not by itself that archive. The paper-mail page says when the original still stays, and it sends the shredding question to the fiduciary. This page does not reopen it. Naming helps you find the voucher inside the ten years. It does not shorten them. Do not delete a folder because it looks old: retention follows the document type and your fiduciary's instruction, not the age of the filename.

## Who should keep filing by hand

Keep filing by hand if a handful of files a week already follow one pattern and one person owns the folder. Automation is how you stop a second pattern from starting, not a prize for tidiness.

Do not start if yesterday's files have five names for the same supplier. Fix the spelling in the accounting list first. A model will reproduce every variant you leave in the examples.

## A made-up example: the supplier with three spellings

A made-up example: an office of 22 people. The same supplier appears as three spellings in filenames. The office lead picks the spelling from the creditor list and uses one pattern for a month. About one in eight suggestions is wrong, usually the delivery date instead of the invoice date. After the month, confident files move on their own. Payroll PDFs sit in a limited folder. No count of minutes is claimed. The change is that a search for the supplier and the month returns one set of names.
