## The difference between digitalisation, automation and AI

The difference between digitalisation, automation and AI is what each step does with the same piece of work. Digitalisation turns information into data a computer can hold: the supplier invoice arrives as a PDF instead of on paper. Automation lets a fixed rule act on that data without anyone clicking: the PDF is filed and sent to the right person for approval. AI handles the part no rule can describe: it reads an invoice or an email that has no fixed layout and pulls out the fields. Each step needs the one before it.

This is for owners and office leads in a Swiss SME who have been told to "do something with AI" and want to know which of the three they are actually missing. One office example runs through all three: the supplier invoice.

<ol class="blog-flow">
  <li><strong>Digitalisation</strong><p>The invoice exists as a file, in a place everyone can find.</p></li>
  <li><strong>Automation</strong><p>A written rule files it and routes it for approval.</p></li>
  <li><strong>AI</strong><p>A model reads what the rule cannot: an unfamiliar layout, a line in an email.</p></li>
</ol>

## Digitalisation: the invoice becomes a file

Digitalisation means the information exists as data, not that anything happens to it. The paper invoice gets scanned, or the supplier sends a PDF to a shared invoices mailbox instead of a personal one. Nobody walks to the filing cabinet any more. Someone still opens every file, reads it, decides who approves it, and types the amount somewhere.

That is already useful: the invoice can be searched, forwarded and kept. It does not save the work around it. In Switzerland part of this step is already done for you. The QR-bill finally replaced the old payment slips on 1 October 2022, and according to [SIX](https://www.six-group.com/en/products-services/banking-services/payment-standardization/standards/qr-bill.html) its Swiss QR code contains all the information needed for the payment in digital form.

## Automation: a rule moves the file

Automation means a rule you can write down does the step, the same way every time. Every PDF that reaches the invoices mailbox is saved in this month's folder. Invoices from a known supplier go to the person who ordered from them. Above an amount you set, a second person has to approve. When both have approved, the file goes to bookkeeping.

The rule does not understand anything. It checks a sender, a folder or an amount and acts. That is its strength: same input, same result, cheap to run, easy to check afterwards. It breaks where the input has no fixed shape. A rule can read the amount from a QR code. It cannot tell from a free-text line which project a delivery belongs to.

## AI: a model reads what has no fixed shape

AI is the step that reads or judges content a rule cannot describe. The [OECD definition](https://oecd.ai/en/wonk/ai-system-definition-update) puts it this way: an AI system "infers, from the input it receives, how to generate outputs such as predictions, content, recommendations, or decisions". Inferring is the difference from a rule, which only follows.

In the invoice example: forty suppliers, forty layouts, some invoices only as text in an email. A model reads each one and returns supplier, amount, due date and a suggested cost centre. It is usually right, not always. So the result goes into the same approval step as before, and a person confirms until you have seen enough runs to trust it.

## The one mistake: buying AI for a missing step

The common mistake is to buy "AI" when the real gap is a missing digital or rule-based step. If invoices still land on one person's desk on paper, a model has nothing to read. If nobody has decided who approves which invoice, the model extracts perfect fields that then go nowhere. In both cases the money goes into the third step while the first or second is still missing.

Ask three questions about the process, in this order. Is the input already a file in a shared place? Is there a rule you could write on one page? Is there a part left that someone has to read and interpret? Only the third answer calls for AI. Many office processes stop at the second: a rule is cheaper per run and gives the same answer every time.

  <p>No. It is the right tool wherever the step can be written as a rule. AI earns its place where input varies too much for a rule, and it still needs the digital input and the rule-based steps around it.</p>
