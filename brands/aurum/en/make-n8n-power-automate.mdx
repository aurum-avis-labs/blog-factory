## Make, n8n, and Power Automate after the process is clear

Pick the tool after you can say what the workflow does. Make fits a firm that needs cloud glue between systems it already pays for, and that can live with a vendor processing the run under a contract. n8n fits when you want the option to run it on infrastructure you control, and someone operates updates, backups and access. Power Automate fits when Microsoft 365 is already the desk.

There is no single winner for a Swiss SME. The stack you already have decides more than a feature list. Before any of the three, the workflow has to pass the filter in [which process to automate first](/prozess-check/blog/which-process-to-automate-first). If what you need is a draft inside Word, Outlook or Teams, a licence often beats a build. That fork is in [Copilot or build a workflow](/prozess-check/blog/copilot-or-build-a-workflow).

## Same jobs, three answers

Compare the tools on the job you actually have. A scheduled file from two exports. A reminder when a quote has sat for seven days. A PDF dropped in a folder that should land as a draft in the accounting tool, still waiting for a person to confirm.

| Job | Make | n8n | Power Automate |
| --- | --- | --- | --- |
| Who it is for | A small team that wants a cloud flow in days and can sign a DPA | A firm that wants the run on a host it controls | A firm that already lives in Microsoft 365 |
| Where the run lives | On Make's cloud. Confirm region and contract before live data | On n8n Cloud, or on a server you run if you self-host | In your Microsoft tenant |
| Who looks after it next year | The vendor runs the platform. You still own the scenario and errors | You, if you self-host: updates, backups, who may edit the flow | A Microsoft admin: licences, environments, connector access |
| A human still approves | Put the approval in the scenario | Same | Approvals in Teams when the firm already works there |
| Skip it when | You cannot accept a cloud processor, or Microsoft already has the glue | Nobody will patch the server, and n8n Cloud is also a no | You are not on Microsoft 365, or systems sit outside your connectors |

Prices move. Check the vendor's current price page before you commit. Guide figures for the build, not for these three tools, are in [what automation costs in Switzerland](/prozess-check/blog/what-automation-costs-switzerland).

## Make: cloud glue, if the contract fits

Make is a cloud service. You draw a scenario, connect accounts, a run happens on their side. That is why a first glue between two SaaS tools can exist in days, without a server in a cupboard.

Personal data means a processing agreement and the region on the plan you buy. Read the page you would sign, not a comparison from last spring. If that region is somewhere your file is not allowed to go, choose another tool.

Make is a poor fit when nobody will open the error log. A scenario that fails quietly for three weeks is worse than the Monday paste, because people trust a file that stopped updating. Name who gets the failure mail before you turn it on. Skip Make when the firm already runs the same flow in Microsoft 365, or when your rule keeps this file category off US or EU SaaS workflow tools.

## n8n: control over the host

Self-hosting keeps execution on infrastructure you chose. That matters when cloud workflow tools are a hard no. Control is operations: updates, backups, who may edit a workflow. In a firm of 15 people that is often the same office lead who already builds the Monday sheet. If they will not do server work, and you will not pay a host to do it, self-hosted n8n becomes a project that stalls after the demo.

n8n Cloud is back to a processor, contract and region, like Make. The self-host benefit does not transfer to the cloud plan by brand name. Skip n8n when nobody will maintain it, or when Microsoft already contains the flow and only a premium connector is missing. Self-hosting does not make a vague process safer.

## Power Automate: when Microsoft is the office

If mail, files and approvals already sit in Exchange, SharePoint and Teams, people and permissions are often already there. Some flows work with what the Microsoft 365 subscription includes. Premium connectors and desktop automation cost more. Check the connector you need against the licence you have before you design around it. A firm that turns on Power Automate «because it was in the tenant» and then finds every useful connector is premium has not saved the build.

Data sits in the Microsoft cloud your tenant uses. A processing agreement still applies. A flow that copies mandate files into personal OneDrive is the same mistake as a paste into a private chat. Skip Power Automate when you would buy Microsoft only for the flow tool, or when the systems that matter sit outside your connectors. If you wanted a model to draft text in the apps people already open, that is a Copilot question from the opening section.

## Switzerland: data location, then the workflow

Personal data in a run needs a processing agreement when a vendor touches it, a known place where the run happens, and no customer files in a private chat beside the official flow. The same Swiss Data Protection Act covers this as the rest of the office.

Practical order:

1. List the fields that move. Names, addresses, invoice PDFs and mandate notes are personal data.
2. Decide whether a cloud processor is acceptable for those fields. If it is not, self-hosting is the remaining serious option, and you still need an operator.
3. Read the current DPA and region on the plan you would buy.
4. Only then compare which of the three can see the systems you listed.

Name who may edit the flow as clearly as who may send a customer mail.

## Who should walk away from all three

Walk away when the last ten runs do not look alike. The stop signs are in [when AI makes the process worse](/prozess-check/blog/when-ai-makes-the-process-worse). Walk away when Copilot or ChatGPT already covers the gap. Walk away when the project is to replace bexio or Abacus. These tools glue a gap beside the system of record.

## Three picks, sketched briefly

A made-up example: A 20-person project office in Zug already works in Microsoft 365. A reminder on silent quotes and a draft the owner still sends are Power Automate jobs. Make would duplicate the desk. Self-hosted n8n would add a server nobody wants.

A manufacturer with a non-Microsoft CRM and customer names in a weekly file evaluates self-hosted n8n only if they can name an operator. An agency routing a public form to Slack can use Make in days if someone reads failures and the DPA is signed before live data.

None of these is a result we measured. They show stack, data, and whether someone will still be there in six months when a password expires.
