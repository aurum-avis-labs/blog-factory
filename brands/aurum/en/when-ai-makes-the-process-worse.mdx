## When AI makes the process worse

A model in the middle of a workflow makes that workflow worse when the data shifts, exceptions pile up, nobody owns the run, or customer mail and reported figures leave without a human read. The output looks finished. Hours go up. A wrong number travels further than a manual draft ever did, and the person who used to catch the error is no longer in the path.

This is for owners, ops, finance and office leads in a Swiss SME, often 5 to 80 people, with little or no in-house IT. ChatGPT is already open, or a Copilot licence sits on the desk, and someone wants the next step to be "AI". Run the checklist on the one workflow they named before you buy a tool or a build.

The filter for a workflow still worth trying is in [which process to automate first](/prozess-check/blog/which-process-to-automate-first). Four yes answers there (it repeats, it hurts, it has an edge, the file already exists) are the start. The list below is the stop. One yes is a reason to pause. Two yes answers mean you would automate the mess.

<ul class="blog-checklist">
  <li>The source columns or file names change, and nobody owns the version that counts</li>
  <li>A large share of runs needs a special rule that only one person knows</li>
  <li>No one person may say the run is done or that it is wrong</li>
  <li>Customer mail, or figures for a report, go out without a human read</li>
</ul>

## Tool choice comes after the list

A tool does not replace this list. Copilot in Excel or an agent in the CRM only speeds up work that is already stable. If the file has a new name every Friday, the model's speed becomes risk, because nobody reads every step anymore.

## Bad data

Bad data means the input is not the same thing from week to week. The column was "Hours" last Friday and "Std" this Friday. One export includes credit notes, the next does not, and nobody recorded which version the report uses. The workbook on SharePoint and the one on a laptop disagree, and the meeting still happens.

A model faced with a gap fills it. It produces a total that looks like the last total. Someone forwards that paragraph internally because it reads clean. The error is now in a second inbox, with your company's tone on it.

The [adesso GenAI Impact Report 2026](https://www.adesso.ch/adesso-ch/whitepaper/genai-impact-report-2026-ch.pdf) names data quality and missing processes as the most common hurdles in Switzerland, each cited at 32 percent, ahead of the model itself. Those are adesso's figures, not our survey. The blocker in the office is the file and the missing owner. A different model will meet the same file.

Before any build: one source, stable column names, and a person who may reject a file that arrives in a new shape. If that person does not exist, the checklist has already failed.

## Too many exceptions

Every second run needs a special rule. "This customer is always net 60." "Skip this supplier in August." "The German entity uses the other VAT code." When those rules live in someone's head, a workflow that encodes last month's exceptions becomes a second manual process. Someone still watches every run and now debugs the workflow as well.

Count exceptions on the last ten real runs from the actual files. If you cannot list them, the process is not stable enough for a tool. If you list more exceptions than standard runs, write the rules down and decide which stay manual. Automation is for the path you can describe before the run starts.

A handful of known exceptions, with a queue a person clears, can still be a build. An open list that grows every week is not a first case.

## No owner

Somebody has to be allowed to say the run finished and to stop it when the output is wrong. If that sentence has no name, responsibility sits in a chat log. Three people are "sort of on it". When the output is wrong, each one can point at the tool.

Name one owner before you name a tool. The owner does not have to click every step. They do know the start, the end, and who gets the output. If only one person understands the logic and the office waits while they are on holiday, you have frequency plus a single point of failure. Write the steps so a second person could follow them. A script pointed at logic in one head fails the week that person is away.

## Unchecked customer mail and reported figures

An internal draft is a fair use of a model. Mail to a client, or a figure for the Monday report, needs a person who has compared it to the source.

That is the default wherever personal data is in the text and wherever a number will be reused. A wrong courtesy mail is awkward. A wrong total in a customer status, or in a report the bank or board will see, now leaves the building in a clean font.

The model may prepare. A named person sends, or a named person releases the file. If you cannot say who that is this month, the workflow is not ready.

## A monthly owner mail that went out wrong

Picture a 16-person property management office in Winterthur. No IT department. Each month an admin sends building owners a short status: open tickets, costs, what happens next. The numbers come from a sheet the caretaker updates. Someone suggests a model should write the mail.

One month the cost column is labelled CHF in one building file and left blank in another. A ticket closed on site is still open on the sheet. The model writes a confident total. The admin forwards the mail. An owner replies about a charge that was never in the caretaker's file.

Next step: a person who owns the column names, and a rule that the mail waits until someone has compared the total. A build for the sheet itself waits until those columns stay still for a month. If the sheet, columns and import are already that stable, the question moves to [Excel as a shadow system](/prozess-check/blog/excel-as-shadow-system). This monthly mail was not there yet.

## When you stop, and when you try anyway

Stop when you want the model to invent the judgement: which customer is angry for a fair reason, which exception you grant on purpose, which number "feels right" for the board. Those conversations change every time. A template can help the person who holds them. A workflow that sends the result will make the process worse.

Try anyway when the last ten runs look alike, the columns have an owner, exceptions are a short written list, and a named person checks customer-facing text and any figure that will be reused. Then you are back on the filter in [which process to automate first](/prozess-check/blog/which-process-to-automate-first).

If you are unsure, bring the candidate to the [Process Check](/prozess-check). The hour may end with "not this one". That is a finished result. Six weeks on a tool that cements a chaotic process costs more than 60 minutes of clarity on the live file.
