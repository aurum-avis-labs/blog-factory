## Generate documents from templates automatically: the short answer

To generate documents from templates automatically, you make five moves, and they are the same for quotes, contracts, letters and order confirmations. The fixed wording lives in one template with named fields. The fields are filled from one data source, such as a form, the CRM or a spreadsheet. A script or flow exports a PDF and saves it in a fixed place. A person checks it before it goes out. Prices, dates and legal wording come from the template and the data. AI, if you use it at all, writes one marked free-text part, always as a draft.

This is for owners and office leads in Swiss SMEs who write the same kind of document several times a week. Open last month's quote, save it under a new name, replace the customer, change the figures, hope nothing from the old customer is left in the footer. If you write two contracts a year, none of this pays off.

## The five steps from data to a checked PDF

Each step is small. The work is to decide them once and write them down.

<ol class="blog-steps">
  <li data-step="1"><h3>One template per document type</h3><p>A quote, an order confirmation, a letter: one file each. The wording is written once. Everything that changes is a named field: customer, address, project, amounts, date.</p></li>
  <li data-step="2"><h3>One source for the data</h3><p>The fields come from one place: a web form, the CRM or a spreadsheet row. Not from memory and not from the last document.</p></li>
  <li data-step="3"><h3>Generate and export as PDF</h3><p>A script or flow copies the template, replaces the fields and exports a PDF. The Word or Docs file stays as the editable original.</p></li>
  <li data-step="4"><h3>File it the same way every time</h3><p>One folder logic and one name pattern, for example project number, customer, document type, version. Nobody searches Sent Items afterwards.</p></li>
  <li data-step="5"><h3>Check, then send</h3><p>A person reads the PDF next to the data row and releases it. Only then does the mail go out from the office mailbox, and the send date is written back to the record.</p></li>
</ol>

Step 2 is where most projects stall. If the same customer sits in two programs with two spellings, the template prints whichever one it reads. Decide which program leads first: [how to stop double data entry](/blog/stop-double-data-entry) walks through that decision.

The check in step 5 takes a minute: amounts, address and salutation, attachments, the free-text part. It is why a wrong number does not reach a customer.

## Word or Google Docs: what your templates can already do

For a few documents a week, the mail merge you already have is often enough. Full automation needs a flow on top of it.

In Word, a mail merge fills letters from an Excel table. Microsoft's help page says the column names must match the field names, and that the merge document stays connected to its data source ([Microsoft Support](https://support.microsoft.com/en-us/office/mail-merge-using-an-excel-spreadsheet-858c7d7f-5cc0-4ba1-9a7b-0a948fa3d7d3)). That suits batches of letters, less a quote whose fee table has a different number of rows each time.

In Microsoft 365, Power Automate has a Word Online (Business) connector with the actions «Populate a Microsoft Word template» and «Convert Word Document to PDF» ([Microsoft Learn](https://learn.microsoft.com/en-us/connectors/wordonlinebusiness/)). The same page lists limits that matter for planning: it is a premium connector, rich text and date picker content controls are not supported, and the populate action cannot be used under a conditional-access policy that requires multi-factor authentication.

In Google Workspace, variable chips in Google Docs fill several fields with the same text and export templates with different values. They are available only for eligible work or school accounts, and you fill them by hand ([Google Docs Help](https://support.google.com/docs/answer/13584275?hl=en)). For automatic filling you need a script: Apps Script can replace text patterns in a document with [replaceText](https://developers.google.com/apps-script/reference/document/body) and convert a file to PDF with [getAs](https://developers.google.com/apps-script/reference/base/blob).

Our own download form uses similar pieces: a Google Apps Script logs the request in a Sheet, fetches a PDF from a private Drive folder and sends it by email through Microsoft Graph.

If your business software already produces the quote from its own template, use that first. The gap is usually the documents around it. What your programs offer as interfaces, we clarify in the Check.

## Where AI helps and where fixed wording is safer

AI helps with the free-text parts that differ every time. Everything with a price, a date or a legal effect should stay fixed template wording.

| Part of the document | Comes from | Why |
| --- | --- | --- |
| Name, address, salutation | Data | Copied, never rewritten |
| Prices, quantities, VAT, totals | Data and rules | A wrong number does more harm than a stiff sentence |
| Terms, payment conditions, clauses | Template, approved once | Legal wording changes only on purpose |
| Introduction, «what you asked us for» | AI draft, marked | Differs each time, a person edits it |
| Summary of an email thread for the file | AI draft | Internal, nobody outside relies on it |

The rule that makes this safe: AI writes into one marked field. It never touches the other fields, and a person reads everything before it leaves.

If that text is drafted from a customer's email, the email contains personal data. The Federal Data Protection and Information Commissioner (EDÖB) states that the Swiss data protection act applies directly to AI-based data processing ([EDÖB: KI und Datenschutz](https://www.edoeb.admin.ch/de/ki-und-datenschutz)). Do not paste customer emails into a free chatbot account, and ask your data-protection adviser which service fits. This is practical guidance, not legal advice.

## Signatures: what Swiss law asks for

Most documents need no signature that the law prescribes. Where one is required, only the qualified electronic signature counts as equal to a handwritten one.

<aside class="blog-callout blog-callout--limit">
  <span class="blog-kicker">Limit</span>
  <p>According to the Federal Office of Communications (BAKOM), Swiss contract law follows freedom of form, so few transactions need a qualified electronic signature at all. Where a handwritten signature is required, only a qualified electronic signature under ZertES is treated as equal: one based on a qualified certificate from a recognised provider and carrying a qualified time stamp. Other electronic signatures can be used where no handwritten signature is required.</p>
</aside>

That is the position in Art. 14 para. 2bis of the Code of Obligations, as [BAKOM explains it](https://www.bakom.admin.ch/de/23-welche-rechtskraft-haben-elektronische-signaturen). The Swiss accreditation body keeps a list of the providers that may issue qualified certificates ([BAKOM](https://www.bakom.admin.ch/de/elektronische-signatur-2)).

A quote or an order confirmation usually needs neither. A pasted image of a signature is not a qualified signature: it rests on no certificate and carries no time stamp. Whether a particular contract needs written form is a question for your lawyer, not the template.

## Filing: what to keep, and for how long

Keep the PDF that was actually sent, not only the editable original, because the original changes the next time someone edits the template.

Accounting records and vouchers such as invoices must be kept for ten years from the end of the financial year. Electronic storage is allowed if they stay readable and match the underlying transactions ([kmu.admin.ch](https://www.kmu.admin.ch/de/elektronische-aufbewahrung-der-geschaeftsbuecher)). For quotes and contracts the period depends on the document, so ask your fiduciary or lawyer before you set a deletion rule.

## An example: fee quotes at a 12-person planning office

An example, not a client: a planning office with about twelve people. It sends around ten fee quotes a month for renovation projects, and an order confirmation for each one that is accepted.

Today, the project lead opens the last quote, saves it under a new name, swaps customer and address, retypes the fee table and exports a PDF. Everyone names the file differently, and now and then a previous customer's name survives in the footer.

The build: one Word template for the quote and one for the confirmation. A form for the project lead writes one row per quote into a spreadsheet: customer, address, scope modules from a fixed list, hours or a lump sum. The rates sit in a second sheet that the office manager maintains. Terms and payment conditions never change, so they stay in the template. One field is free text, how the office understood the project.

When a row is marked «create draft», a flow fills the template, exports the PDF, files it in the project folder under a fixed name and mails it to the project lead, not to the customer. The free-text paragraph is drafted by an AI service from the project lead's own notes and marked as a draft. The project lead corrects it and sets the row to «approved». Only then does the flow send the mail from the office mailbox and write the send date into the row. That date is where a reminder can start: see [how to follow up on quotes without losing them](/blog/quote-follow-ups).

For scale: one document type with one data source is the kind of clearly bounded task the guide price of CHF 3'200–4'800 is meant for. Several document types or systems move towards the larger packages. The fixed price comes in writing after the Check.

## When not to automate documents

Skip it when the volume is low or the wording is not settled.

- **Low volume.** For a few documents a month, one template file with clear fields and a checklist is enough.
- **Unsettled wording.** If three versions of your terms circulate, choose one first. Automation would only spread the disagreement.
- **Negotiated contracts.** Each has its own clauses and often a lawyer's review. Use the template for the frame, not the content.
- **No owner.** Every template needs a named person, a date of the last change and an archive of old versions. Otherwise an outdated payment term goes out on every document.
