**Meeting projects** are how Vemoir groups calls, notes, and follow-up on one client or one piece of work. You can create a project, name it, give it a client or group, describe it, and pick an icon. From the menu bar you choose that project before you press record, so the audio is filed there from the start.

If you forget, the meeting can still land in Local Recordings. You can drag it into a project afterward. Filing it first is calmer, because the project's glossary and context are the ones in scope while the record is built.

## What meeting projects contain

A project holds date-grouped meetings, the generated records, actions, decisions, documents, exports, and the project context. The dashboard shows a recap, open work, recent decisions, pinned documents, and recent meetings. Search inside the project covers meetings, transcripts, artifacts, actions, and decisions on the Mac.


Actions you edit at project level change the same records you see on the meeting. A task does not fork into two copies because you opened it from the client page. New project-level actions and decisions stay attached to a source meeting you select.

Archive, restore, and delete exist for both projects and meetings, with local cleanup. Deleting a project removes its meetings, transcripts, generated records, actions, decisions, speaker data in scope, and the recording folders. That is a real deletion on this Mac, not a hide. Export anything you still need before you confirm it.

## File the call before you record

1. Create the project once, with the client name you want on the dashboard.
2. Add a short description if several projects would otherwise look the same.
3. Put the terms that must be spelled a certain way in that project's glossary. The glossary is not shared across projects.
4. In the menu bar recorder, select the project, then start. Microphone and system audio are still the two local tracks. The project only decides where the meeting is filed.
5. After you stop, open the project dashboard if you want the recap rather than a single meeting.


Imported files can be assigned to a project too, and they go through the same local pipeline as a recorded call. A file is not split into mic and system audio unless it already was.

## What a project is not

It is not a shared team workspace. Another person does not get your project by signing in. It is not a cloud folder. It is not a speaker directory for the whole company. Voice profiles, if you opt in, stay on the Mac and can be deleted in Privacy settings. Unknown speakers stay anonymous until you remember them.

It is also not a substitute for the meeting vendor's official recording. If the client requires Teams or Zoom's own archive, use that button as well. Vemoir is your local record, with no bot in the participant list.

Browser tools do not have projects. [/tools/transcribe-recording](/tools/transcribe-recording) turns a short file into text after the call, up to 15 minutes, three successful runs a week, with no speaker labels. Ongoing client work belongs in the Mac app.

## Where leaving calls unfiled is better

Meeting projects are the better choice when you will have more than one call with the same client and you want glossary, actions, and documents in one place. They are the worse choice when:

- This is a single call you will export and forget. Local Recordings is enough. A project you never open is clutter, and a project you later delete takes its meetings with it.
- Several people must edit the same list of tasks in a browser. A cloud workspace they already pay for is built for that. You can still keep the audio on the Mac and paste the minutes you choose to share.
- You are about to delete a project to "clean up" and you have not exported the notes. Deletion removes the recordings in that project. Pause and export first. Apple Notes, if you set a folder, is one destination, described separately.

Ask Vemoir can be scoped to one meeting, one project, or the active library. Opening Ask from a project starts a scoped conversation. Archived projects are left out. That is useful when the question is "what did this client decide," and less useful when you wanted every meeting on the Mac including ones you archived.

Set the project in the menu bar, then record. The layout of a finished record is under [the record](/#record).

## A week of calls on one client

Monday you create "Northwind" and set the client name. You add three glossary terms before the kickoff and select Northwind in the menu bar. The recording files there. Wednesday you join from a different meeting app. The project is the same, because filing does not depend on Teams versus Meet. You type two manual notes during the call. They stay attached to that meeting, with their own provenance, and they show up when the project dashboard lists open work.

Friday a colleague forwards an old M4A. You import it into Northwind. It is not a live mic-plus-system capture. It is the file, processed locally. It sits in the date list with the other meetings. Ask, if you open it from the project, can look across the project's active meetings, not across archived ones. If you archive last year's Northwind work, those meetings drop out of that scope. They are not deleted until you delete them.

When the engagement ends, export the notes you must keep, including an Apple Notes folder if that is your archive, then delete the project only if you want the local meetings gone. The dashboard is a view. The files are the meetings. Nothing in the project is uploaded because you gave it a client name. Cloud text, if you turn it on later, is a separate activation and stays text-only.

## Frequently asked questions

### Can I pick a meeting project before I hit record?

Yes. The menu bar recorder includes project selection so the call is filed before capture starts.

### Can I move a meeting later?

Yes. You can drag meetings between Local Recordings and projects.

### Does each project have its own glossary?

Yes. Preferred terms, aliases, and definitions live on that project. The original transcript stays the evidence.

### What does delete do?

Deleting a project removes its meetings, transcripts, generated records, actions, decisions, speaker data in scope, and recording folders on this Mac.

### Will my colleagues see the project?

No. It is local. Sharing is a separate step, through export or macOS sharing of the parts you choose.

### Do actions edited on the project change the meeting?

Yes. Project-level edits update the same source records shown in the meeting.

### Is there a project in the browser tools?

No. The free tools transcribe a file you already have. They do not file live calls under a client.

### What Mac is required?

Apple silicon, macOS Sonoma 14.2 or later, at least 8 GB of memory and 10 GB of free storage. 16 GB is recommended for long meetings. Intel Macs are not supported.

Create the client as a project once, select it in the menu bar, and record. The dashboard on [the record](/#record) is where the open work shows up afterward.
