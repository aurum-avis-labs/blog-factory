To **import an audio file on a Mac** and get a transcript, you already have the recording. The job is to run speech-to-text on that file without turning the import into an accidental upload. On Vemoir you drop the file into the Mac app (picker or drag and drop), assign it to a project if you want, and process it through the same local pipeline as a meeting you recorded from the menu bar. In the browser, you can do the same for a short clip without sending the file to Vemoir.

This is the after-the-call path. It does not record a live meeting and it does not add a bot to Zoom or Teams. If you still need to capture the next call on the Mac, that is [menu-bar recording](/#capture), not import.

## What you can import on a Mac

Vemoir imports common local audio files: **MP3, M4A, WAV, AIFF, CAF, and FLAC**. Those are the formats to export from a recorder, a meeting app's local folder, or an interview kit before you drag them in.

A few files people try that are not this list:

- **MP4 video.** The Mac app's import list is audio files. If Zoom gave you a movie, look in the same dated folder for `audio_only.m4a` instead of importing the video. The browser tool does accept MP4 (and MP3, M4A, WAV) for a short file.
- **VTT or TXT.** Those are already text. Import will not improve a caption file. Clean it, or turn it into notes, but do not pretend it is audio.
- **A link to a cloud recording.** Import needs bytes on disk. Download the audio first, then import. Downloading a cloud transcript is not local transcription; the vendor already ran speech-to-text.

Voice memos on iPhone usually land as M4A after you AirDrop or Files them to the Mac. That is an ordinary import once the file is local.

Requirements for the Mac app: Apple silicon (M1 or newer), macOS Sonoma 14.2 or later, room for the models. Intel Macs are not supported. Internet is for setup and model downloads. After that, processing can run offline.

## Import an audio file on a Mac in Vemoir

1. Get the file onto the Mac. Name it so you can find it next month. A date and a client slug beat `recording(3).m4a`.
2. Open Vemoir. Create or select a **project** if the call belongs under a client. You can file the import before processing, the same way you can file a live recording before you press Record.
3. Use the file picker, or drag the file onto the app. One file becomes one meeting record in the library.
4. Let local transcription finish. The authoritative transcript is built from the imported audio. Speaker separation runs on the Mac. You can rename speakers afterward. Remember-this-speaker profiles are opt-in and encrypted; unknown speakers stay anonymous.
5. Edit minutes, decisions, and actions on the Mac. Notes you type are folded into that record. Share through native macOS sharing, and share only the parts you choose.

Nothing in that list uploads the audio to Vemoir. Cloud text models (OpenAI or Anthropic with your own key) are opt-in for generated prose only. They do not transcribe the file, and the app does not silently fall back to them.

If you want a transcript without installing the app and the clip is short, skip to the browser section. If the file is a local Zoom recording, the folder hunt is documented in [transcribe a local Zoom recording](/blog/transcribe-zoom-local-recording).

## Import vs recording the call yourself

Import is for audio that already exists: a colleague's Zoom local recording, a handheld recorder, a dictation you will not repeat, an interview exported from another tool.

Live capture is for the next meeting on **this** Mac: microphone plus system audio, no bot in the list. Import cannot add system audio that was never in the file. If the M4A is already mic-only, you will not recover the remote side by importing it into a better app.

Do not import a silent file and expect a transcript. If playback is empty, fix capture next time rather than re-importing. The troubleshooting pattern (mic vs system audio) is a recording problem, not an import problem.

## The browser path: short files, no install

The free [transcribe recording tool](/tools/transcribe-recording) runs in your tab. You choose MP3, M4A, WAV, or MP4. **The file is not uploaded to Vemoir.** A public Whisper model downloads once; later runs can work with the network off. Check the Network tab if you need to show someone that the audio did not post to a server.

Limits as of September 2026:

- **15 minutes** per file
- **3 successful runs per week**
- **No speaker labels**
- **No live meeting recording** in the browser

Split a long file if you stay in the tab, or use the Mac app for the whole recording. For interviews and consent paperwork, the same local-in-the-tab idea is spelled out in [transcribe an interview without uploading](/blog/transcribe-interview-without-upload).

Want this on a file you already have, without a vendor upload? [Open the transcribe recording tool](/tools/transcribe-recording).

## After import: what you can share

The useful export is usually the minutes, decisions, and actions, not the audio. Keep or drop the recording according to your retention choice. Vemoir can remove the per-meeting audio folder after a successful pass if that is how you configured storage. The written record can still point at transcript lines on the Mac.

Do not call the output a certified transcript. Do not call it GDPR-certified or privileged. Consent and deletion remain yours. If the imported file was someone else's recording, importing it does not fix missing consent.

## When another path is better

- **The official copy must live in Teams or Zoom.** Importing a personal download does not replace the tenant recording. Use the platform's recorder when that is the file legal will ask for.
- **You need a shared company library today.** A file on one Mac is not a workspace. Export the notes; do not pretend import created a team archive.
- **The file is 12 minutes and you only need raw text once.** The browser tool is less setup.
- **You are not on Apple silicon.** The Mac app will not run. Use a tool that supports your OS, or the browser tool for a short clip.

## Frequently asked questions

### Can I import an audio file on a Mac that I recorded on my phone?

Yes, once the file is actually on the Mac (AirDrop, Files, USB) and in a supported audio format. The phone recording is still only whatever the phone's microphone heard. It will not include a Zoom call that played on a different device.

### Does import upload the meeting to Vemoir?

No. The Mac app processes locally. The browser tool does not send the file to Vemoir either. Exporting, or opting into a cloud **text** model with your own key, is a later, explicit choice. Transcription of the audio stays on the device or in the tab.

### Which formats does Vemoir import?

MP3, M4A, WAV, AIFF, CAF, and FLAC in the Mac app. The browser tool accepts MP3, M4A, WAV, or MP4, with the 15-minute cap.

### Can I import while a live meeting is still going?

You can import an old file at any time. Import does not capture the live call. For the live call, start recording from the menu bar with microphone and system audio allowed.

### Do imported files get speaker labels?

On the Mac app, speaker separation runs locally. You rename labels; profiles are opt-in. The browser tool does not separate speakers.

### What if the imported transcript is the wrong language?

The app language (English, German, French, Italian, Dutch) is independent from the transcription model. Pick a model that covers the spoken language. Parakeet v3 covers 25 European languages. Other Whisper variants have their own coverage. This page does not rank them on accuracy.
