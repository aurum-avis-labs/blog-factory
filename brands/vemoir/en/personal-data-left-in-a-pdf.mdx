Personal data left in a PDF is easy to miss because the page looks finished. The text layer can still hold a name, a town, a birth date, an email, or a number that identifies someone, even when you only meant to share the argument.

Sending the file is the moment that matters. A viewer can select the text, copy it, and search it. A black highlight drawn in a word processor is not the same as removing the text.

<ul class="blog-facts">
  <li><span class="blog-kicker">Layer</span><strong>Text</strong><p>If you can select it, it can leave with the file.</p></li>
  <li><span class="blog-kicker">Look</span><strong>Short spans</strong><p>Names, places, dates, contact details, identifiers.</p></li>
  <li><span class="blog-kicker">Check</span><strong>Every page</strong><p>Headers, footers, and the last page count too.</p></li>
</ul>

## What usually stays in the file

A CV, a clinic letter, an invoice, and a project note fail in the same places. The name is in the heading. The town sits next to a region code. The birth date is written out in words, not only as digits. The email and the phone number sit in a line of ordinary prose. An identifier hides in a row that looks like administration.

Job titles, product names, and the point of the document are not personal data by themselves. The risk is the detail that points at a person.

A scan of a paper page is different. If there is no text layer, selecting does nothing, and the picture still shows the detail. You cover the picture, or you do not share that page.

## How to read a page before you send it

<ol class="blog-steps">
  <li data-step="1"><h3>Select a paragraph</h3><p>If the words highlight, they are in the file as text.</p></li>
  <li data-step="2"><h3>Read the edges</h3><p>Headers, footers, and the signature block are where names and numbers linger.</p></li>
  <li data-step="3"><h3>Cover, then open the copy</h3><p>Look at the file you will actually send, not the one you edited.</p></li>
</ol>

  <span class="blog-kicker">Limit</span>
