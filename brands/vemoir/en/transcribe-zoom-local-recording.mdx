If you need to **transcribe a Zoom recording** after the call, the file on your computer is often an audio track, not a ready-made transcript. Zoom only generates a separate transcript file when the meeting was **recorded to the cloud** on a **paid** plan with cloud recording and audio transcription turned on. When you choose **Record to this computer** (the usual path on free accounts and many paid users), Zoom saves video and audio locally. You get M4A or MP4 files you can turn into text yourself.

This guide walks through where those local files live on Mac and Windows, how that differs from cloud VTT transcripts, and how to run **transcribe zoom recording** workflow in the browser without sending your meeting audio to a server.

## Why there is no transcript in the Zoom folder

After a local recording finishes, Zoom creates a dated folder with files such as `video*.mp4`, `audio*.m4a`, and sometimes `audio_only.m4a` depending on your Zoom version and recording options. There is **no** `.vtt` transcript in that folder because [audio transcription for cloud recordings](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0064927) applies only when the meeting is saved to Zoom’s cloud, not when it is saved on your device. Zoom’s own help article on [enabling audio transcription](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0065911) states that transcription **only applies to cloud recordings**, not computer recordings stored locally.

Cloud recordings on eligible Pro, Business, Education, or Enterprise accounts can produce a **VTT** file after processing, as described in Zoom’s guide on [recording file formats](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0064394). Local computer recordings use **MP4** (video) and **M4A** (audio-only) instead. If you expected a transcript email from Zoom but recorded locally, the behavior is consistent with Zoom’s documentation: you already have the audio; the text step is up to you.

## Where Zoom saves local recordings on Mac and Windows

Default storage is under **Documents/Zoom**, with one subfolder per meeting (often named with the date and topic). Zoom documents these defaults in [Finding your computer and cloud recordings](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0058006):

- **Mac:** `/Users/[Username]/Documents/Zoom`
- **Windows:** `C:\Users\[Username]\Documents\Zoom`

Your path can differ if someone changed **Local recording storage** in the Zoom desktop app: profile picture → **Settings** → **Recording** → **Open** or **Change** next to the storage location (same article). If a recording seems missing, Zoom’s [troubleshooting guide](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0083769) recommends opening that folder from Settings and checking whether the meeting was cloud-recorded instead.

Inside the meeting folder, open the **audio-only** file for transcription. Zoom’s format doc names local audio `audio[random number].m4a` by default; many installs also expose a file named **`audio_only.m4a`**. Either file is the sound track you want. Keep the whole folder until you have a transcript you trust; local recordings exist only on that computer, and Zoom does not keep a backup copy on their servers.

## Cloud VTT vs local M4A or MP4

| What you have | Typical files | Transcript from Zoom? |
| --- | --- | --- |
| Cloud recording (paid + cloud recording enabled) | MP4, M4A, optional **VTT** transcript | Yes, after cloud processing, if audio transcription is enabled |
| Local / computer recording | **M4A**, **MP4**, optional `chat.txt` | No automatic VTT; you transcribe from audio |

The VTT file is plain text with timestamps, useful for captions and search. Local M4A is smaller and enough for speech-to-text. You do not need the video file for a transcript unless you want to align text to visuals later.

## Free accounts, paid plans, and "Record to this computer"

Local recording is available on free and paid Zoom accounts ([computer recordings](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0058006)). Cloud recording with an automatic transcript depends on a licensed plan and admin settings. During the meeting, choosing **Record to this computer** instead of **Record to the cloud** determines whether you will later find a VTT in the Zoom web portal or M4A/MP4 on disk. Teams that discuss data handling with clients often prefer local capture plus transcription in their own browser: the file stays on the laptop, and you can confirm behavior in the Network tab.

## Step by step: transcribe the local Zoom audio in your browser

1. **Confirm the recording is local.** In the Zoom app, open **Settings** → **Recording** and note the storage path. You should see a recent folder under `Documents/Zoom` (or your custom path).
2. **Find the audio file.** In that folder, select `audio_only.m4a` if present; otherwise use the `audio*.m4a` file Zoom created (see [file formats](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0064394)).
3. **Check length.** The free tool on vemoir.ch handles recordings up to **15 minutes** per file. Longer meetings need a different workflow (see below).
4. **Open the Zoom transcription tool.** Go to [/tools/transcribe-zoom-recording](/tools/transcribe-zoom-recording) and add your M4A (or MP3, WAV, MP4 as supported).
5. **Run transcription.** Processing happens in the tab. The audio file is **not uploaded** to Vemoir; the speech model loads in the browser, and later runs can work offline once the model is cached.
6. **Copy or export the text** for your notes, email, or project folder.

For a generic file (not Zoom-specific UI), the hub at [/tools](/tools) lists related tools. If you already have text and need structured minutes, see [/tools/meeting-notes-from-transcript](/tools/meeting-notes-from-transcript).

## How to verify nothing was uploaded

Because the file stays on your machine, you can confirm privacy with the browser’s developer tools:

1. Open the tool page and start transcription with your Zoom M4A.
2. Open **Developer Tools** (Chrome or Edge: **View** → **Developer** → **Developer Tools**, or right-click → **Inspect**).
3. Select the **Network** tab, then filter by **Fetch/XHR** if available.
4. Run the job again if needed and watch for requests that send your audio bytes to a remote host.

You should see model or asset downloads on first use, not a multipart upload of your meeting recording. If your organization requires local-only processing for all lengths, the [Vemoir Mac app](https://apps.apple.com/app/id6794693630) keeps transcription on the device and supports longer meetings, speaker profiles, and full meeting records (see [how capture works](/#capture) and [minutes and record](/#record)). Vemoir records system audio and your microphone from the menu bar; **no bot joins** the Zoom call.

## When the browser tool is enough vs when to use the Mac app

The browser path fits a **short local Zoom clip** you already exported, up to **15 minutes**, up to **three successful runs per week**, with **no speaker labels** and **no live meeting capture** in the tab. Swiss German and other dialects in public Whisper models typically appear as **Standard German** text, not dialect spelling.

Choose the Mac app when:

- The meeting ran **longer than 15 minutes** and you do not want to split the M4A manually.
- You want **speaker separation**, glossaries, and **Ask Vemoir** over past meetings.
- You prefer to **record the next call on the Mac** (Teams, Zoom, Meet, and others that play audio on the device) instead of hunting folders afterward. See [supported meeting apps](/#platforms).

## Frequently asked questions

### Does Zoom transcribe local recordings automatically?

No. Zoom’s cloud **audio transcription** produces a VTT file only for **cloud** recordings when the feature is enabled on an eligible paid account. Local **Record to this computer** files are audio and video on disk, not a transcript ([Zoom help](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0065911)).

### Where is my Zoom recording on a Mac?

By default, look in `/Users/[Your name]/Documents/Zoom`, then the folder for that meeting ([Zoom help](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0058006)). Use **Settings** → **Recording** → **Open** in the Zoom app if you changed the storage location.

### Where does Zoom save local recordings on Windows?

The default path is `C:\Users\[Username]\Documents\Zoom` ([Zoom help](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0058006)). Each meeting gets its own subfolder.

### Which file should I transcribe: MP4 or M4A?

Use the **M4A** audio-only file when available (`audio_only.m4a` or `audio*.m4a`). It is smaller and avoids decoding video. MP4 works if that is all you have ([file formats](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0064394)).

### Is the free Zoom transcription tool really offline and private?

Your Zoom file is processed in the browser and is not uploaded to Vemoir. The first run downloads the model; you can use the Network tab to inspect traffic. Internet is needed for that initial download; later runs can work offline once cached. Speaker labels and live recording are not part of the browser tools.

### What is the 15-minute limit?

Files longer than **15 minutes** are outside the free browser tool’s scope. Import the full local recording in the **Vemoir Mac app**, or split the M4A into segments if you must stay in the browser (mind consent and retention policies for any copies you make).

### Can I get speaker names from a local Zoom M4A in the browser?

No. Public browser models do not separate speakers. For diarization on the Mac, use Vemoir’s local speaker profiles ([capture and models](/#capture)).

### Do I need a paid Zoom plan to transcribe a local recording myself?

No. Local recording is available on free and paid accounts ([computer recordings](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0058006)). Paid cloud plans add Zoom-hosted transcripts for **cloud** recordings, not for replacing local audio transcription.

### Will Swiss German stay Swiss German in the browser?

Usually not. Browser tools based on public Whisper models tend to output **Standard German** text from Swiss German speech. Plan accordingly for quotes and client-facing documents.
