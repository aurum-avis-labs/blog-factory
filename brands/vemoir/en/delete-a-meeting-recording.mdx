To **delete a meeting recording** in Vemoir, you first decide which layer you mean: purge the audio only, remove one meeting from the library, or delete the whole project folder. Those actions are separate on the Mac. Clearing the tape does not automatically remove the transcript or the minutes.

Below is the order most people want: keep notes after audio is gone, delete a single bad call, or wipe a client project when the engagement ends. Consent and retention rules stay yours; this page is not legal advice.

## When to delete a meeting recording

A finished meeting in Vemoir is a small stack of local files and database rows:


<ol class="blog-flow">
  <li><strong>Audio</strong><p>Microphone and system tracks, if you kept them.</p></li>
  <li><strong>Transcript</strong><p>Built locally after you stop.</p></li>
  <li><strong>Project</strong><p>The folder that groups several meetings.</p></li>
</ol>


- The microphone track and the system-audio track, if you kept them.
- The transcript built from that audio after you stopped.
- Summary, actions, decisions, documents, and any manual notes you typed during the call.
- Speaker labels for that meeting. A remembered voice profile, if you created one, lives elsewhere.

Search and Ask Vemoir read the library. If the meeting is gone, those tools stop seeing it. Archived meetings are already hidden from ordinary Ask scope. Deletion goes further: the knowledge records tied to that meeting are removed.

The capture itself never records the screen. macOS permission for the call audio is **System Audio Recording**. The tap is audio-only. Deleting a recording is not the same job as revoking that permission.

## Drop the audio and keep the record

Many people want the notes on Monday and the audio gone by Friday. That is a storage choice, not a full delete. If you only need to share the text, you can also export or copy minutes without sending the recording, as described in [share notes without the recording](/blog/share-notes-without-the-recording).


<ul class="blog-checklist">
  <li>Decide whether you need the minutes after the audio goes</li>
  <li>Purge audio in Storage without deleting the meeting</li>
  <li>Delete the meeting or project only when the whole record should vanish</li>
</ul>


During setup, or later in **Settings → Storage**, you decide whether future meetings keep their audio. Each meeting keeps the choice that was active when it was created. A meeting recorded while retention was off does not grow an audio file because you change the setting afterwards.

After processing succeeds, audio cleanup runs by default. If you had chosen to retain audio, Storage can still **purge the retained audio** for a finished meeting. The library then shows a clear unavailable state for playback. The transcript, summary, actions, and decisions stay, because they were already written.

Play controls (track choice, seek, elapsed time) exist only while retained audio is there. After a purge, there is nothing to scrub.

Failed or interrupted processing is the exception. Recovery audio is kept so you can retry. Do not treat a failed run as "already deleted." Finish or discard it on purpose.

## Delete one meeting

Deleting the meeting removes that sitting from the library: transcript, generated records, actions and decisions that belong to it, and the recording folder. The sidebar and project dashboard no longer list it. Ask Vemoir no longer answers from it.

If the same decision was also visible on the project dashboard, it was the same record, not a second copy. Removing the source meeting removes that record from the project view as well.

Rename is not delete. You can rename a meeting title inline. The generated title stays as a fallback if you clear the name. That does not touch the audio.

Archive is not delete either. Archive takes a meeting or project out of the active list. Restore brings it back. Use archive when you might need the sitting again and do not want it in everyday search.

## Delete a project

A project is the folder you filed the call under before you pressed record (or the one you dragged the meeting into later). How projects group meetings is covered in [meeting projects](/blog/meeting-projects). Deleting the project removes, in one local cleanup:

- its meetings
- transcripts
- generated records, actions, and decisions
- speaker data that belongs to that project scope
- recording folders

Project search, the recap, pinned documents, and recent decisions go with it. There is no separate cloud copy inside Vemoir for those rows. The library is an owner-only database on the Mac.

A glossary you built for that client (preferred terms and aliases) is project data. It does not survive the project. The original transcripts are gone too, so there is no later pass that can rebuild the minutes from audio you already purged.

If you only wanted one bad call gone, delete the meeting. Leave the project.

## What deletion does not reach

A few things sit outside the recording folder. Check them if the goal is "nothing about this client remains on this Mac."

**Voice profiles.** `Remember this speaker` stores an encrypted profile only after you approve it. You review, disable, anonymize, or permanently delete profiles from Privacy settings. Deleting a meeting does not, by itself, wipe a profile you asked the app to keep. Unknown speakers never got a profile.

**Apple Notes.** If you exported a meeting, Vemoir stores the note identifier so a later export updates the same note instead of making a duplicate. The note itself lives in Apple Notes. Removing the meeting in Vemoir does not erase that note. Delete it in Notes if you need it gone.

**Clipboard and files you already sent.** A Markdown copy, a document you saved outside the app, or an email you sent is outside the library. Vemoir exports can be evidence-free (the copy goes out without the transcript links). That file is yours afterwards.

**Your own API key route.** If you turned on an OpenAI or Anthropic key for text, audio still never left for transcription. Content-free receipts (provider, timing, outcome, no transcript text) can be exported or deleted in Privacy and Data. They are not the recording.

**The guided sample.** The sample meeting is marked Sample and can be deleted in one action. It is excluded from normal library counts and does not silently create a voice profile.

## Retention you set before the next call

The least surprising setup is to decide retention once, then delete by exception.

1. Open **Settings → Storage** and choose whether new meetings keep audio after processing.
2. Record from the menu bar. You start and stop. Nothing joins the call.
3. Read the minutes. If the audio has done its job, purge it and keep the record.
4. If the whole sitting should disappear, delete the meeting.
5. If the client engagement is over, delete the project and then check Privacy for any voice profile you no longer want.

Internet is not required for these steps once the app is installed. Deletion is local.

If you are unsure which sitting you are about to remove, use library search first, as in [search past meetings](/blog/search-past-meetings). ## Frequently asked questions

### Does deleting the audio delete the transcript?

No. Purging retained audio removes playback. The transcript and the generated record stay until you delete the meeting.

### Can I delete one meeting and keep the others in the project?

Yes. Meeting deletion is scoped to that sitting. The project and its other meetings stay.

### What if processing failed halfway?

Recovery audio is kept so the run can be retried. Purge or delete only after you have decided you do not need that recovery.

### Are speaker names removed when I delete the meeting?

Labels for that meeting go with it. A voice profile you explicitly saved is removed from Privacy settings, not by the meeting delete button.

### Does this wipe a note I already sent to Apple Notes?

No. The exported note remains in Apple Notes until you delete it there.

### Is there an undo?

Treat delete and project delete as final local cleanup. Archive is the reversible step. There is no cloud recycle bin for the library, because the library is not in a Vemoir cloud.

### Does the browser tool keep a copy?

The free tools on the site run in the tab and do not upload the file. They are a different path from the Mac library. Deleting a meeting in the app does not affect a file you still have in Downloads.

The next recording can keep or drop its audio from the start. Set that in Storage, then use the menu-bar recorder described under [capture](/#capture).
