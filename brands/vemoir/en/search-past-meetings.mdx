You can **search past meetings** on the Mac that recorded them: titles, transcripts, artifacts, actions, and decisions, without sending the library to a hosted search index. Vemoir's library search and Ask Vemoir both stay on the machine unless you have explicitly routed text generation to your own API key.

Search answers "where did we say that." Ask answers a question and can point at a line. They are different controls. This page is about finding the sitting, then asking inside a scope you choose.

## Where search past meetings actually looks

Project search covers meetings, transcripts, artifacts, actions, and decisions. The project dashboard adds a recap, open work, recent decisions, pinned documents, and recent meetings, with jumps back to the source record.

That is enough when you remember a client, a phrase, or an owner's name. It is the wrong tool when you want a composed answer ("what did we promise Acme about the rollout date"). For that, open Ask Vemoir and pick a scope.

The scope choices are fixed:

- one meeting
- one project
- the active library

Opening Ask from a meeting or a project starts a new conversation in that scope. Older threads stay in Ask history, including their scope, so you can return to last week's question without mixing it into today's.

Archived meetings and archived projects are excluded. Deletions remove the knowledge records that pointed at them. If you purged only the audio and kept the meeting, search still finds the transcript and the notes. Playback is gone. The words are not.

## Find a meeting from the keyboard

Library destinations use Command-1 through Command-6. **Command-F** focuses meeting search. Arrow keys move through the project sidebar and the meeting list. Drag and drop between Local Recordings and a project still works. Search does not replace filing.

A practical order when you cannot remember which Tuesday it was:

1. File calls into a project before you record, using the menu-bar project picker. Search is faster when the client is already the folder.
2. Press Command-F and type a name, a product term, or a decision phrase.
3. Open the meeting if the row is the one you wanted.
4. If you need the line, switch to the transcript, or ask inside that meeting so the answer can cite a passage.

A project glossary (preferred spellings and aliases) helps later notes use the right name. Search still matches the original transcript. The original wording is the evidence. The glossary does not rewrite history so that an old nickname disappears from the tape.

## Ask inside one meeting, one project, or the library

Ask Vemoir is a conversation with a boundary. Ordinary questions are narrowed before the local model writes. A request that needs the whole scope uses a bounded pass over the meetings in that scope, and the context receipt tells you the coverage even when the answer only links its strongest sources.

Answers can include evidence links: open the meeting, land on the transcript, and see the cited passage. The model is asked to cite the strongest lines, and the app caps a single answer at 24 unique sources. A long library question will not attach every paragraph it looked at.

Completed answers show which model wrote them. If you switch between the local models installed on the Mac (Qwen3 4B on most machines, gpt-oss-20b on high-memory Macs), the next turn is re-planned. Earlier messages stay as they were.

Text generation can use Apple Intelligence where the Mac has it, or a local model you downloaded. An OpenAI or Anthropic key is optional, text only, and off until you activate it. Transcription of the original audio does not move to that provider. If the provider fails, the turn stops. There is no silent swap to another model.

None of this searches a meeting that was never recorded into the library. A calendar event with no audio is not a result.

## How this differs from Zoom or Teams search

Zoom and Teams search inside their own cloud. The scope is whatever your licence and the organizer allowed: cloud recording, transcript add-ons, retention rules. Vemoir search runs only on meetings that landed in your Mac library through capture or import. A phrase from last quarter's client call will not appear if that call lived only in a host's Zoom cloud and you never imported the audio.

Cloud notetaker bots add another index, usually on a vendor server. Vemoir does not merge those indexes with your local library. If your policy forbids bots, local search is the trade you accept: everything findable stayed on the Mac you control.

## Keep the library easy to search later

Search is faster when each call has a project before you press record. Use the menu-bar project picker so the client name is the folder, not a guess after Command-F. Rename imports to something you will remember (client plus date), even though the transcript still holds the spoken words.

Speaker profiles and project glossaries improve labels in new minutes. They do not rewrite old transcript lines, so search for what was said, then read the decision row if the name changed in the minutes later.

Want the next call filed before you hunt for it? Vemoir records from the menu bar into the project you pick first. [Capture and models](/#capture) explains permissions and where audio goes.

## What never shows up

Search and Ask read the active library. They skip:

- archived meetings and projects
- meetings you deleted
- the contents of a voice profile (embeddings are not in search, exports, or ordinary logs)
- internal evidence keys, which are stripped from the visible answer
- a manual note presented as if it were a verbatim line (manual notes keep their own mark)

The guided sample is visibly marked Sample. Delete it when you are done with the tour so it does not sit next to real clients in search.

If Command-F returns nothing, the usual causes are dull ones. The word was only spoken and the transcript used a different spelling. The meeting is archived. The meeting lives in another project and you are searching inside one project. Or the audio was imported under a file name you no longer remember, while the spoken phrase is what search would have matched inside the transcript.

## When a transcript quote is the wrong result

A hit in the transcript proves someone said the words. It does not prove the room agreed. Decisions in Vemoir are their own records: wording, a responsible person, and a date, editable after the call. Actions have an owner, a due date, and a status. Search can find those rows without making you skim the tape.

When you need a line you can stand on, ask inside the meeting and follow the evidence link. When you need the commitment, open Decisions on that project.

## Frequently asked questions

### Can I search Zoom cloud transcripts inside Vemoir?

No. Vemoir indexes the Mac library only. Import the audio file, or record the next call locally, then search that meeting.

### Does search past meetings upload the library?

No. Meeting search runs on the Mac. Ask runs locally by default. A cloud language model is used only if you turn on your own key for text, and even then the audio stays on the machine.

### Can I search across every client at once?

Yes. Ask can use the active library as the scope. Project search is the view for one project. Archived items are out of both.

### Why did a deleted meeting vanish from old answers?

Deletions remove the knowledge records. The library does not keep a shadow copy for search.

### Will Ask invent a speaker name?

Unknown speakers stay anonymous. A renamed label applies to that meeting. A remembered profile is used only when you approved it and the match clears the app's checks.

### What is the keyboard shortcut for meeting search?

Command-F focuses meeting search. Command-1 through Command-6 jump between library destinations.

### Does this work offline?

After the models you selected are downloaded, search and Ask do not need a network. The first download does.

### Can I search a Loom or Zoom file I have not imported?

Not until it is in the library. Import the audio, or record the next call from the menu bar, and then search that meeting.
